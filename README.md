# GrantNavigator
Данный проект создан в ходе изучения курса разработки полного цикла. Первоначально взятая идея проекта звучит так: "Грантовый кабинет: создание заявок, отслеживание дедлайнов, ИИ-проверка соответствия критериям конкурса". В репозитории ведутся обновления README, помимо базовых компонентов он содержит записи типа "лайфстайл" для простоты понимания.

Проект состоит из 5 лабораторных работ, выполняются они последовательно, расширяя проект. Ниже будет вестись описание разработки.

## Лабораторная 1. Интерфейс приложения и каркас frontend.

*Цели работы*:
- Определить основные экраны и пользовательские сценарии проекта;

### Шаг 1. Определите назначение приложения, основные пользовательские сценарии и необходимые экраны. 
#### Назначение приложения:
Грант.Навигатор - веб-приложение для участников грантовых конкурсов. Оно предназначено для организации работы с грантовыми проектами: поиска подходящих конкурсов, подготовки заявок, контроля сроков подачи и предварительной проверки заявки на соответствие требованиям выбранного конкурса.

Приложение позволяет пользователю хранить свои проекты, связывать их с подходящими грантовыми конкурсами и отслеживать процесс подготовки заявки. При подготовке заявки есть доступ к ИИ-ассистенту, который проверяет её относительно требований выбранного грантового конкурса. Проверка включает наличие необходимых разделов и информации, соответствие установленным требованиям, а также оценку качества и полноты сформулированного содержания. По результатам проверки пользователь получает перечень обнаруженных проблем и рекомендации по доработке заявки.

#### Пользовательские сценарии:
1. Регистрация и настройка профиля:
   - пользователь регистрируется в системе, указывает необходимые персональные данные и подтверждает согласие на обработку данных;
   - пользователь может указать интересующие направления грантов, чтобы в дальнейшем использовать их при подборе подходящих конкурсов;
   - после всего цикла регистрации он получает доступ к основному функционалу приложения.
2. Создание и редактирование проекта:
   - пользователь переходит в раздел со своими проектами и создаёт новый проект;
   - в проекте пользователь заполняет основные сведения о своей инициативе: название, описание, цели, задачи и другие необходимые данные;
   - проект можно сохранить, вернуться к его редактированию и использовать при подготовке заявок на различные грантовые конкурсы.
3. Поиск и выбор грантового конкурса:
   - пользователь просматривает доступные грантовые конкурсы и выбирает подходящий конкурс;
   - для поиска конкурса пользователь может использовать фильтры и текстовый поиск;
   - в карточке конкурса отображается основная информация: название, описание, требования к участникам, критерии оценки и срок подачи заявки;
   - после выбора конкурса пользователь может начать подготовку заявки и связать конкурс с одним из ранее созданных проектов;
   - создаётся заявка, связанная с выбранным конкурсом и проектом пользователя.
4. Подготовка и проверка заявки:
   - пользователь открывает выбранный конкурс и связанную с ним заявку;
   - на этапе подготовки пользователь редактирует содержание заявки в соответствии с требованиями конкурса. После заполнения заявки пользователь может запустить проверку с помощью ИИ-ассистента.
   - ИИ-ассистент анализирует содержание заявки относительно известных требований и критериев выбранного конкурса и формирует результат проверки: выявленные несоответствия, недостаточно раскрытые пункты и рекомендации по улучшению заявки;
   - пользователь вносит необходимые изменения и при необходимости повторяет проверку.
5. Контроль сроков и статуса заявки:
   - пользователь отслеживает свои заявки и сроки подачи в отдельном разделе;
   - для каждой заявки отображается информация о выбранном конкурсе, сроке подачи и текущем статусе. Например, могут использоваться следующие статусы (пока считаем, что изменение статуса осуществляется вручную):
      - Подготовка: заявка находится в процессе заполнения;
      - Готова к подаче: подготовка заявки завершена;
      - Подана: заявка отправлена на конкурс;
      - Рассматривается: заявка находится на рассмотрении организаторами;
      - Результат получен: по заявке опубликован результат конкурса.

ИТОГОВЫЙ ЖИЗНЕННЫЙ ЦИКЛ ЗАЯВКИ: 
```
Регистрация → создание проекта → поиск конкурса → выбор конкурса и проекта → подготовка заявки → проверка соответствия → доработка → подача заявки → отслеживание результата
```

scripts/
  create_tables.py  создаёт таблицы в БД

| `grant_sections` | Обязательный раздел заявки конкретного конкурса (например, «Бюджет») | М:1 к `grants` |
| `projects` | Проект пользователя | М:1 к `users`; 1:М к `applications` |
| `applications` | Заявка — связывает проект и конкурс | М:1 к `grants`, `projects`, `users`; 1:М к `application_answers`, `check_results` |
| `application_answers` | Текст пользователя по одному разделу заявки | М:1 к `applications` и `grant_sections` |
| `check_results` | Один запуск ИИ-проверки заявки (история проверок сохраняется) | М:1 к `applications`; 1:М к `check_issues` |
| `check_issues` | Одна строка результата проверки (замечание по разделу) | М:1 к `check_results` |

Все связи реализованы через внешние ключи (`ForeignKey`) с каскадным удалением: удаление проекта удаляет его заявки, удаление заявки удаляет её ответы и историю проверок.

### Шаг 4.	Реализуйте создание, чтение, изменение и удаление данных для основных сущностей проекта. Операции должны работать с PostgreSQL через SQLAlchemy.

Для `users`, `grants`, `projects`, `applications` реализованы создание, чтение (список и по id), изменение (`PATCH`) и удаление. Отдельно: `PUT /applications/{id}/answers` сохраняет ответы по разделам, `POST /applications/{id}/check` запускает ИИ-проверку (пока по простым демо-правилам: пустой раздел — ошибка, короткий — предупреждение; настоящую модель подключим позже).
